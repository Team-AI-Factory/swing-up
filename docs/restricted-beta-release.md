# Restricted 25-company beta release policy

Adopted 15 October 2026 from `Swing_Up_24_Hour_Launch_Tradeoffs_2026-10-08.pdf`.

This is an implementation and release checklist, not a release certificate. The local candidate has not been published or deployed. Exact shipped-version release evidence is still required. No qualifying live Serious Alert is established by the local tests.

## Launch versus later goals

A restricted beta does not depend on producing 500 new profiles per day, broad market coverage, five trading sessions, 20 distinct real cases, two consecutive scale-up windows, or a proven long-term investment track record. Those remain separate coverage, operating-observation, usefulness, and expansion/performance goals. Removing them from beta launch prerequisites does not improve the pipeline or supply missing evidence.

The fixed 25-company cohort and main-scanning pause remain. Existing per-alert safety, source verification, current actionable quotes, materiality/direction, required final review, accounting holds and the shared spending limits remain. No new services, larger limits, faster schedules or subscriptions are introduced. A newly admissible case can still consume existing review/storage capacity; an unchanged hosting bill is not guaranteed. On 15 October the user explicitly approved deployment and live verification within existing limits even if Railway/R2 usage changes slightly. This does not authorize higher caps or unrelated configuration changes.

## Implemented boundary

- Initial event scope is direct, quantified company events. Indirect supplier/sector/macro cases and speculative event families are explicitly parked. A numeric event metric must be bound to its verified primary/official receipt. Existing materiality and causal checks still apply.
- Direct company valuation remains a separately labeled assessment, not a newly announced event. The separately reviewed `sec-annual-single-scenario-v1` route can qualify one appropriate, reproducible annual SEC earnings or FCF scenario without raising scanner confidence or lowering the generic confidence threshold. All non-method evidence, economic applicability, extreme-value, quote, required-review and publication checks remain. Missing or unreconciled cases are held before paid admission for this route. Its arithmetic policy, deliberately narrow annual-period coverage, unproven predictive performance, saved-evidence binding and unchanged budget/deduplication boundaries are documented in [single-scenario-qualification.md](single-scenario-qualification.md).
- Short company context is a separate event-scoped object, never a full verified profile or a new-profile count. It retains exact issuer identity, dated annual business evidence and an exact relevant direct official event. Unknown customers/moat stay unknown. Customer/moat-dependent or ambiguous claims still require the full relevant information.
- A versioned risk-only policy supports Serious Watch Out for a verified direct material downside risk. It is not a fallback for failed valuation. Required review, risk relevance, source/document completeness, direction, quote/session checks and durable publication/delivery binding remain. Targets and expected-return percentages are withheld. Buy/Sell cannot inherit this exception.
- One authenticated official disclosure can already advance without a fixed secondary-news count when all required baseline/market checks pass. Disputed claims still need corroboration. Existing company-reported attribution and copied-source independence checks remain.
- Authenticated web feeds use the existing scoped read key. No credential is generated or persistent access expanded. Research Watch rows display saved reasons and dates; stale/unverified prices and targets are omitted. A parked row is not approval or an executable opportunity. Reopening still follows substantive evidence or bounded technical-retry rules.
- Focused 3–6-role reviews and optional historical analogs predate this change. They are not claimed as newly implemented fixes.

## Required evidence before opening the beta

1. Freeze the exact deployed code, fixed cohort, source scope, main pause and spending/accounting configuration. Keep the approved existing limits and verify no unrelated configuration changes are included.
2. Resolve each case's exact missing facts/quotes or display its parked reason. A technical error is never approval. No event or paid review is forced to make the feed nonempty.
3. On that exact shipped version, pass valid, stale, duplicate, wrong-company, missing-figure, timeout, financial-transport, risk-only relabeling, customer-dependent short-profile, auth and budget-hold cases. Verify complete required reviewer roles and durable approval/rejection reasons.
4. Complete a real-model review within existing authorized limits. Local mocked-provider tests are safety regressions, not live model proof.
5. Verify isolated positive and negative authenticated web-delivery controls on the same version, including duplicate suppression and test/live separation. An earlier revision's test receipt does not certify this revision.
6. A real Serious Alert needs its own authentic approval and saved delivery receipt. Without one, say “No qualifying Serious Alert yet.” No long-term investment accuracy or daily opportunity guarantee is made.
